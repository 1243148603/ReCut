# CutMap 通用化说明（2026-09-30）

> 这份文档回答：「换个省/市/县，怎么用这套软件？」
> 本轮做的是**批次 3（去重庆默认值）+ 批次 2（预览页做成交付物）**；
> 批次 1（投影坐标系提示）经确认**不做**；批次 4/5（配置外置、通用性闸门）后置。

---

## 一、这轮改了什么

### 1. 去掉「重庆」默认值（批次 3）

以前新建任务时，范围里预填的是重庆的 `105.3 28.1 110.2 32.2`，换个地方要先删掉这些数字；
现在**范围留空**，由你来定：

| 位置 | 变化 |
|---|---|
| 拼接裁剪窗口 | 打开时范围为空；预设下拉不预选（预选等于又绑回某个区域） |
| 下载窗口 | 打开时区域为空；同样是「预设 / 边界 / 手填」三种来源 |
| 裁剪范围预设 / 任务预设的「新增」 | 空白模板（不再以「重庆全域」起手） |
| 内置「重庆全域」预设 | **保留**，作为可选模板 |

**新增的范围来源按钮**（换区域时最省事的一步）：

| 窗口 | 按钮 | 做什么 |
|---|---|---|
| 拼接裁剪 | 用输入范围 | 取已添加输入 DEM 的并集，一步填好西/南/东/北 |
| 拼接裁剪 | 用已有瓦片… | 选一个已有瓦片目录，从 `layer.json` 结构反推范围 |
| 下载 | 用已有 DEM 范围… | 多选已有 DEM，取并集（"想补下相邻这片"） |
| 下载 | 用已有瓦片… | 同上，从瓦片目录反推 |

（「选行政区划」本来就有：勾选「按行政区划」→「选择边界…」，数据覆盖全国 34 省 / 363 市 / 2840 县。）

**CLI 不再写死 `D:\Map`**：11 处默认路径改为从当前目录向上找仓库根（找不到退回当前目录），
在任意目录下都能跑。

### 2. 预览页做成交付物（批次 2）

`terrain_viewer.html` 以前写死了重庆（瓦片路径、镜头中心、最大层级、采样点、期望高程、
自检瓦片坐标），换区域**看不了、还会假报警**。现在：

- **路径**：`?tiles=<相对路径>`（默认仓库里那份）
- **镜头与层级**：从该瓦片集的 `layer.json` 读 `bounds` 与 `maxzoom`；读不到时用兜底值，
  也可用 `?bounds=w,s,e,n` / `?maxzoom=N` 显式覆盖
- **采样点**：按 bounds 生成（中心 + 四角内缩 12.5%），**不再内嵌期望高程**——只报"瓦片里存的高程"，
  核对请与源 DEM 同点比较；换区域不会假报警
- **自检瓦片**：最深级那一块按 bounds 中心算（不再写死 `14/25968/10752`）
- **底图默认关闭**（要底图加 `?basemap=1`）；断网/内网时地形照样能看
- **Cesium 随仓库分发**：`viewer/vendor/cesium/`（373 个文件，约 13 MB），不再依赖 CDN
- **降级**：Cesium 加载失败时，数据自检（只碰本机瓦片）照常给出结果

`serve.py` 增加 `--tileset`（或自动发现含 `layer.json` 的目录）：指定的瓦片集会被挂到
`/__tileset__/`，**瓦片放在哪个盘都能预览**（不必先拷进仓库树），启动后直接打印可用的预览地址。

## 二、换个区域怎么用（操作流程）

以「四川省某市」为例：

1. **下载 DEM**（工具条「下载 DEM 数据…」）
   - 区域来源：选行政区划（推荐，按真实相交只下需要的分幅）或手填经纬度范围
   - 保存目录自选；下载支持暂停/续传（整批并发 4 幅）
2. **拼接裁剪**（工具条「新建任务 → 拼接裁剪」）
   - 添加刚下载的 DEM（可多选）
   - 点「用输入范围」填范围；或勾「按行政区划」+「选择边界…」按边界裁（边界外自动补平坦裙边）
   - 覆盖检查通过后才能开始；`dem_clipped.tif` 落在指定位置
3. **切片**：输入 `dem_clipped.tif`，层级用自动推导值（比参考值更深不会更清晰）
4. **打包**：勾要的产物（前端瓦片 / 算法 GeoTIFF、是否打 zip）；`layer.json` 的
   name/description/version 自己填
5. **预览**：在仓库根目录
   ```
   python serve.py --tileset <瓦片目录>
   ```
   打开终端里打印的地址（形如 `http://127.0.0.1:8080/terrain_viewer.html?tiles=…&debug=1`）
6. **交付**：瓦片目录里的 `README.txt`（随打包一起产出）已写明前端怎么接、
   服务器必须声明 `Content-Encoding: gzip`、以及怎么用预览页先验一遍

> 注意：**不要直接把 .terrain 目录拷进前端就完事**——服务器必须为 `.terrain` 声明
> `Content-Encoding: gzip`，否则 Cesium 一片空白还不报错。README.txt 里有各服务器的写法。

## 四、明确不做 / 后置

| 项 | 原因 |
|---|---|
| 投影坐标系输入提示（旧计划批次 1） | 已确认不做：数据链路（Copernicus 经纬度 DEM + gdalwarp 输出恒为 EPSG:4326）不会产生投影输入 |
| 任务配置外置 `--config`（批次 4） | 是新能力不是解绑，后置 |
| 通用性闸门 `generality-gate`（批次 5） | 后置 |
| 自动重投影 / mercator 剖分 / 非中国边界数据源 | 同旧计划：会改像元尺寸、前端剖分未定、DataV 只覆盖中国 |

**留一条未查完的疑点**（调试副产品，供以后参考）：CTB **直切 Copernicus COG**
（`data/inputs/dem/N28_E105.tif`）得到的瓦片内容与源 DEM 明显不符——各层级都更平滑、
均值差数百米；而合成斜坡栅格（高程 = 经度×1000）切片完全正确（期望 550 m、实测 551 m），
说明 CTB 映射没问题，疑点在 COG 文件本身（其 overviews 或像素中心原点口径）。
**不影响主链路**（下载 → gdalwarp 拼接 → 切片，该链路验证一直通过）。
