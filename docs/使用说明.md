# CutMap 使用说明

> **一句话**：Windows 桌面应用；拼接裁剪走 GDAL，切片以子进程调用 `ctb-tile.exe`
> （全捆绑分发，用户机器无需装任何环境）；任务串行队列执行；下载源可配置
> （URL 模板）；产物分**前端瓦片目录**（Cesium 标准 + `layer.json`）与
> **算法数据**（裁剪 GeoTIFF + 元数据 json）两条线，各自可选 zip 打包。
>
> 本文按实际操作顺序写，每一步说清楚点哪里、填什么、看什么。
> 只想跑其中一步的，直接跳到对应小节。

## 0 安装

### 方式一：安装包（推荐）

双击 `CutMap-<版本>-Setup-win-x64.exe`。

- **不需要管理员权限**，装到 `%LOCALAPPDATA%\Programs\CutMap`
- 自动建开始菜单与桌面快捷方式
- 在「设置 → 应用 → 已安装的应用」里能看到 CutMap，可以从那里卸载

卸载：桌面或开始菜单找到 CutMap，或在「应用和功能」里点卸载。
卸载不会删除你产出的瓦片与 DEM 数据——它们不在安装目录里。

### 方式二：绿色版

解压 `CutMap-<版本>-win-x64.zip`，直接运行里面的 `CutMap.App.exe`。不写注册表。

> ⚠ 解压后**不要改动目录层次**。程序从 exe 所在位置逐级往上找 `ctb\bin\ctb-tile.exe`，
> 把 `ctb\` 挪走会起不来。

### 运行要求

Windows 10/11 x64。**不需要**装 .NET、Anaconda、GDAL——运行时与 GDAL、CTB 都在包里。

## 1 认识界面

打开后是一个窗口，分三块：

```
┌─────────────────────────────────────────────────────────┐
│ 新建任务… │ 下载 DEM 数据… │ 暂停 │ 暂停队列 │ 取消 │ 历史… │ 导出日志… │  ← 工具条
├─────────────────────────────────────────────────────────┤
│ 类型 │ 任务 │ 状态 │ 进度 │ 说明                          │  ← 队列
├─────────────────────────────────────────────────────────┤
│ 日志                                                     │  ← 日志（深色，滚动）
├─────────────────────────────────────────────────────────┤
│ 状态栏（当前在干什么）                          [进度条]  │
└─────────────────────────────────────────────────────────┘
```

**「下载 DEM 数据…」是工具条上的独立入口**，不在「新建任务…」里面——
因为下载常常是单独一件事，不必每次都走一遍新建任务向导。

**「新建任务…」里是三个按钮**：拼接裁剪 / 切片 / 打包。加上下载，一共四件事，
每件都能单独跑。

## 2 完整流程（第一次用，从头走一遍）

### 2.1 下载 DEM 分幅

**点工具条「下载 DEM 数据…」。**

| 步骤 | 怎么操作 |
|---|---|
| 1 | **下载源**：下拉里选。默认是「Copernicus GLO-30 官方源（AWS）」，免注册直下。要换内网镜像点右边的「管理源…」新增。 |
| 2 | 确认下面那行灰字 **URL 预览**——那是实际会去请求的地址。拼错了这里能一眼看出来。 |
| 3 | **区域**：两种填法。①「预设」下拉选「重庆全域」；② 或者勾上「按行政区划」，点「选择边界…」挑具体省市县。 |
| 4 | 填完区域后，下面会显示 **「将下载 N 幅（首幅 … 末幅 …），约 X.XX GB」**。这里就该核对一下：重庆全域按外接矩形是 30 幅，勾了「按行政区划」是 21 幅。 |
| 5 | **保存到**：点「浏览…」选一个空目录。 |
| 6 | 点 **「开始下载」**。 |

**下载过程中**：
- 队列里那一行会显示 `3/30` 这样的进度，日志里逐幅打印
- 想暂停点工具条 **「暂停」**——**这是唯一支持运行中暂停的任务类型**，
  恢复后按 Range 续传，不会重下已完成的
- 想停掉点 **「取消当前任务」**

**下载完成后**会弹一句 **「要现在接着做拼接裁剪吗？」**：
- 点「是」→ 直接打开拼接裁剪对话框，刚下的分幅已经预填好了
- 点「否」→ 回主界面，随时可以自己新建

> **断网了怎么办？** 直接重新开始同一个下载任务即可。已经下完的会自动跳过
> （先比对远端长度再决定），下了一半的会从断点续传。

### 2.2 拼接裁剪

**点「新建任务…」→ 选「拼接裁剪」。**

对话框分三块：

**① 输入 DEM**
- 点「添加 DEM…」，**可以一次多选**（比如 30 幅分幅全选上）
- 列表里逐幅显示：文件名、尺寸、坐标系、像元（角秒）、范围
- 加错了选那一行点「移除选中」，或点「清空」重来

**② 裁剪范围**（两种模式，二选一）

| 模式 | 怎么用 |
|---|---|
| **矩形**（默认） | 「预设」下拉选「重庆全域」，或直接在 西/南/东/北 四个框里手填经纬度 |
| **行政区划** | 勾上「按行政区划边界裁剪」，点「选择边界…」，在弹窗里搜索或展开树选具体区县（**可多选**，选多个会合并成一个掩膜） |

**③ 输出**
- 「输出文件」点「浏览…」选个位置，默认给的是 `dem_clipped.tif`
- 「重采样」一般不用改（`bilinear` 适合连续地形）
- 「同时输出算法元数据 json」**默认勾着**——勾着才会给算法侧产出那份 json

**底部的覆盖检查**会实时告诉你输入盖不盖得住目标：
- 绿灯「覆盖检查通过」→ 可以点「开始」
- 红灯「输入盖不住目标：东边缺 0.2003°（约 18.9 km）」→ **「开始」是灰的**，
  必须补输入或改范围

> **为什么要有这道检查？** 盖不住的话 gdalwarp 照样跑完、CTB 照样切片，
> 产出的是一片没有意义的瓦片——而 CTB 不处理 nodata，那些值会被当成真实高程
> 编进去，前端看到的是一片平齐的"台地"而不是空洞。宁可在这里拦住。

点 **「开始」**。跑完在日志里会看到尺寸与格式摘要。

### 2.3 切片

**点「新建任务…」→ 选「切片」。**

| 步骤 | 怎么操作 |
|---|---|
| 1 | 「输入 DEM」点「浏览…」选上一步产出的那个 GeoTIFF |
| 2 | 选完下面会显示这一幅的摘要（尺寸 / 坐标系 / 像元 / dtype / nodata） |
| 3 | 「最深层级」默认勾着**「自动」**，后面括号里是**按当前像元尺寸推算的参考层级** |
| 4 | 下面那行会显示 **「最深 N 级，共 X 个瓦片，约 Y GB，预计 Z 分钟」** |
| 5 | 「输出目录」点「浏览…」选个空目录 |
| 6 | 点 **「开始切片」** |

**关于「最深层级」**：
- 保持「自动」就是最合理的——按像元尺寸推算，再深不会更清晰
- 手填一个**比参考值更深**的层级时，那行提示会变橙色并写明
  「比参考值 N 深：不会更清晰，瓦片数每级约 ×4」
- 填到**瓦片数失控**的量级（超过 200 万），「开始切片」**直接变灰**，
  并写出超过上限的具体数字。这是拒绝，不是提醒

**切片过程中**：
- 进度条按 ctb-tile 的实时输出走
- 想停点 **「取消当前任务」**——会终止子进程并清理临时文件

> **切片不能中途暂停。** 点「暂停」会弹窗说明原因：切片是单个子进程在跑，
> 没有可以插等待点的循环。要停只能取消，之后重跑。
> 下载是唯一支持真暂停的——它有分块读写的循环。

**跑完后**，任务行会显示 `223,495 个瓦片，最深 14 级`。
**留意有没有失败**：软件不止看进程退出码，还会检查 stderr 与瓦片数对账
（`ctb-tile` 失败时退出码仍然是 0，只看退出码会把坏产物当成功）。

### 2.4 打包

**点「新建任务…」→ 选「打包」。**

这一页决定**要哪几套产物**。两个勾互相独立，可以只要一套。

**① 要哪些产物**

| 勾选 | 产出 |
|---|---|
| ☑ **前端产物** | 瓦片目录 + `layer.json` + `README.txt`（部署说明） |
| ☑ **算法产物** | 裁剪 GeoTIFF + 同名元数据 json |

- 只给前端 → **不勾**算法产物
- 只给算法 → **不勾**前端产物（那切片步骤可以根本不跑）

下面两个输入框分别是**已有的瓦片目录**与**裁剪 GeoTIFF**。
所以**打包不必紧跟切片**——手上有一份瓦片目录，随时可以单独来这一页补 `layer.json`。

**② layer.json**（只有勾了前端产物才用得上）
- `name` / `version` / `description` 是可改的
- `format=heightmap-1.0`、`scheme=tms`、扩展名小写 `watermask` 是格式要求，
  **不开放编辑**——填错了前端就加载不了
- **`bounds` 与 `maxzoom` 不用填**：从瓦片目录实际内容反推，不会跟数据对不上

**③ 输出**
- 只有要打 zip 时才需要填「zip 输出到」

点 **「开始打包」**。

## 3 只跑其中一步

四件事都能单独跑。常见情形：

| 我想…… | 怎么做 |
|---|---|
| **已有多个 DEM，想直接出瓦片** | 走「拼接裁剪」把它们合成一块，再走「切片」。这是链路的正确顺序——多个 1° 分幅各切各的，产出的是一堆互不衔接的瓦片集，前端按一张 `layer.json` 加载会缺一大片 |
| **已有瓦片目录，只想补 `layer.json`** | 走「打包」，只勾前端产物，填上那个目录，**不用重跑切片** |
| **已有裁剪好的 GeoTIFF，只想切** | 直接走「切片」 |
| **只给算法侧数据，不要瓦片** | 走「拼接裁剪」产出 GeoTIFF + json。或者走「打包」时**不勾前端产物** |
| **想把瓦片打包成 zip** | 走「打包」，勾上前端产物与「同时打 zip」 |

## 4 把瓦片部署到前端

把打包产出的目录整个拷到前端项目的静态资源位置，例如 `public/terrain/`。

### ⚠ 服务器必须声明 `Content-Encoding: gzip`

**这是"瓦片都生成了，前端却一片空白"的根因。**
CTB 输出的 `.terrain` 是 gzip 压缩的，Cesium **不在 JS 里解压**，
它依赖浏览器透明解压——而这只有当响应带 `Content-Encoding: gzip` 时才会发生。

缺这个头的症状非常误导：**瓦片请求全是 200**、`layer.json` 也解析正常，
但 globe 永远停在 0 级，屏幕上没有地形。

```nginx
location ~ \.terrain$ { gzip_static off; add_header Content-Encoding gzip; }
```

Apache：`Header set Content-Encoding gzip`。
**不要用 `python -m http.server`**——它不加这个头。

验证：`curl --compressed -o t.bin <瓦片URL>` 应得到 **8452 字节**（不加是 86 字节左右）。

> 打包产出的 `README.txt` 里也写了这一段，它会跟着瓦片目录一起交付——
> 拿到产物的前端不一定会来问你。

### 前端代码

```javascript
terrain: await Cesium.CesiumTerrainProvider.fromUrl('/terrain', {
  requestWaterMask: true,
  requestVertexNormals: true,
}),
```

CesiumJS 1.136 起旧的构造器与 `readyPromise` 写法已移除，只能用 `fromUrl`。

### 别把瓦片提交进 git

22 万个文件、约 1.3 GB。在前端项目的 `.gitignore` 里排除 `public/terrain/`。

### 本地看一眼效果

仓库自带一个本地服务器与预览页：

```bash
cd D:/Map && python serve.py --port 8080
# 浏览器打开 http://127.0.0.1:8080/terrain_viewer.html
```

页面带**自检面板**：绕过 Cesium 直接探瓦片，检查返回体是否已被浏览器解压、
字节数是否 8452；并在数据区四角取点解高程与源 DEM 对照。
**排查"传输对了但没解压"这类故障，看面板比开 F12 快。**

## 5 把数据交给算法侧

勾了「算法产物」的话，裁剪的 GeoTIFF 旁边会有个**同名 json**：

```json
{
  "format_version": "1.0",
  "file": "dem_clipped.tif",
  "crs": { "epsg": 4326, "wkt": "GEOGCS[...]" },
  "bounds_wgs84": [105.3, 28.1, 110.2, 32.2],
  "size_px": [17640, 14760],
  "resolution": { "degrees": [...], "arcsec": [1.0, 1.0], "metres_approx": [26.7, 30.7] },
  "dtype": "Float32",
  "nodata": null,
  "source_files": ["N28_E105.tif", "..."],
  "generated_at": "2026-09-29T...Z",
  "software": "CutMap 0.1.0"
}
```

**这些值全部是从 tif 实测的**，不是照抄输入参数——重采样与裁剪取整之后，
"我本来想要什么"和"实际产出是什么"会不一样，而算法侧拿这份 json 就是为了
不再回来问参数。

`source_files` 是参与拼接的源文件清单，便于回溯这批数据的来路。

## 6 任务与队列

- **一次跑一个**，串行。多个任务排队执行，队列里能看到每个的状态与进度
- **右键队列里的一行**，可以：
  - **挂起 / 恢复**——挂起的任务不参与调度，但仍留在队列里
  - **移除**——从队列里摘掉，**不写历史**（与"取消"区分）
- **已开跑的任务不能直接移除**，要先取消
- 工具条 **「暂停队列」**——停的是**调度**：当前任务自然跑完，之后不再开新的。
  与「暂停」（停当前这个任务）是两回事

**状态栏不显示内部任务号**，只给"类型：状态"。

### 历史

工具条 **「历史…」**。每条记录含参数、状态、耗时、产物路径。

- **双击一条记录**（或选中后点「重跑…」）→ **打开对应的参数界面并回填**。
  之所以不直接重跑，是因为点重跑通常是想**改一个参数**再跑
  （换个输出目录、换个层级），直接跑等于逼你再填一遍
- 可以删除单条，或「清空全部」（会二次确认）

### 日志

- 界面上是最近的部分；**完整日志按次启动写在 `%APPDATA%\CutMap\logs\`**
- 工具条 **「导出日志…」** 导出的是**含完整命令行**的版本
  （GDAL 等价命令、ctb-tile 完整参数、任务清单、系统与版本信息），
  发给开发排障用这个

## 7 配置保存在哪

| 内容 | 位置 |
|---|---|
| 下载源（自定义的） | `%APPDATA%\CutMap\sources.json` |
| 任务历史 | `%APPDATA%\CutMap\history.json` |
| 预设（自定义的） | `%APPDATA%\CutMap\presets.json` |
| 运行日志 | `%APPDATA%\CutMap\logs\` |
| 行政区划边界 | 程序目录下的 `resources\`（三个 geojson） |

放 `%APPDATA%` 而不是程序目录，是为了让开发态与安装态行为一致，
也避免升级程序时把配置冲掉。

**换机器**：把 `%APPDATA%\CutMap\` 整个拷过去即可。

## 8 常见问题

**Q：切片跑完显示"成功"，但前端加载是一片空白。**
先看服务器有没有发 `Content-Encoding: gzip`——见 [§4](#4-把瓦片部署到前端)。
用 `serve.py` + 预览页的自检面板能直接确认。

**Q：切片任务"成功"了，但瓦片数不对。**
正常不该发生：软件会把实际瓦片数与预估对账，不一致会判失败并列出逐层差异。
如果你看到的是失败，日志里有每一层"实际 / 预期"的对比。

**Q：能中断切片吗？**
能取消（会终止子进程并清理临时文件），但不能暂停。见 [§2.3](#23-切片)。

**Q：多个 DEM 分幅能不能直接切片？**
要先走「拼接裁剪」合成一块。多个分幅各切各的，产出的瓦片集互不衔接。
不过「拼接裁剪」支持一次多选，所以也是一步的事。

**Q：切片层级填多深合适？**
保持「自动」。界面显示的那个参考值就是按像元尺寸推算的最优值，
填更深不会更清晰，只会让瓦片数每级约 ×4。

**Q：裁剪按行政区划边界，边界外那块是什么？**
是一圈平坦的"裙边"，高度取输入的最低高程。这是刻意的：
CTB 不处理 nodata，直接掩膜会让边界外被当成真实高程编进瓦片，
前端看到的是一片平齐的"台地"。要"边界外黑色空洞"的效果，
用矩形切片 + 前端 Cesium 的 ClippingPolygon 按边界 geojson 裁。

**Q：能换行政区划数据源吗？**
能。`resources\fetch_boundaries.py` 是唯一的数据入口，产出三个 geojson，
字段只有 `name` + `gb`。换源只改这个脚本，软件一行都不用动。
想换回天地图见 `resources\天地图-Key申请教程.md`。

**Q：程序起不来，提示找不到 CTB 工具包。**
`ctb\` 目录必须与 exe 同级或在其上层。绿色版解压后不要改动目录层次。

## 附：无界面用法

`CutMap.Cli.exe` 用于自动化与排障，不依赖窗口：

```bash
CutMap.Cli version          # GDAL 版本与 PROJ 数据目录
CutMap.Cli warp-gate        # 30 幅拼接，对基线校验和（期望 58775）
CutMap.Cli ctb-gate         # ctb-tile 子进程、实时进度、取消、退出码陷阱
```
