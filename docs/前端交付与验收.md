# 前端交付与验收（对照 PRD.md）

> 这份文档回答两件事：**交付出去的东西长什么样**、**PRD 里跟前端/交付相关的条目怎么验**。
> 面向对象：拿到瓦片交付包的前端同学、以及按 PRD 验收的人。

## 一、交付包长什么样（打包任务的产物）

```
<瓦片目录>/
  layer.json              Cesium 的入口（name/description/version/bounds/maxzoom）
  0/ 1/ … 14/             {z}/{x}/{y}.terrain（gzip 流，65×65 heightmap-1.0）
  README.txt              部署说明（部署位置、gzip 要求、边界说明、ClippingPolygon 片段、数据来源）
  boundary.geojson        ← 只有"按行政区划边界裁剪"的产物才有（FR-15）
```

交付包里**不含前端工程**：前端由本项目 `frontend/`（或前端同学自己的 Cesium 工程）消费。
`boundary.geojson` 的文件名由打包统一固定（源文件是 `<裁剪名>.boundary.geojson`，落在 GeoTIFF 旁边）。

## 二、PRD 条目 → 实现 → 怎么验

| PRD | 实现 | 怎么验 |
|---|---|---|
| **FR-05** 产物管理/部署说明 | `README.txt` 含部署位置与 `.gitignore` 提示（`public/terrain/`） | 打包后打开 README.txt 看这两节 |
| **FR-07** 边界外"空洞"路径 | README 给出 ClippingPolygon 可复制片段；`frontend/` 里做成开关 | 前端勾「边界外裁掉」；注意文档已写明**只保证凸多边形正确**，行政区划边界多为凹，正式展示建议用裙边 |

| **NFR-06** 产物可被 Cesium 加载 | `frontend/` 用官方 `CesiumTerrainProvider.fromUrl` 加载；layer.json 契约不变 | `npm run dev` 打开页面，状态应为「地形加载完成 · N 块瓦片」 |

| **OUT-01** 不自研切片引擎 | 仍由 ctb-tile 产出 heightmap-1.0；README/前端说明写明官方已 deprecated 但 Cesium 仍完整支持 | 文档复核 |

## 三、前端工程（`frontend/`）怎么跑

```bash
cd frontend
npm install            # 走不动就加 --registry=https://registry.npmmirror.com
cp .env.example .env.local     # 填 VITE_TERRAIN_URL / VITE_CESIUM_ION_TOKEN（都不入库）
npm run dev            # http://localhost:5173
```

要点：
- 瓦片放 `public/terrain/`（或 `VITE_TERRAIN_URL` 指向任意同源地址）。
- **`.terrain` 必须带 `Content-Encoding: gzip`**：dev 里由 `vite.config.js` 的中间件补（嗅探 magic 才标，未压缩瓦片绝不误标），生产用 nginx（README 有片段）。
- 有 Ion 令牌时底图默认 Bing 卫星影像，无令牌自动落本地离线影像（Natural Earth II）。
- 边界：`boundary.geojson` 按 `kind` 渲染（outline 粗线 / sublimit 细线 / label 标注 / source 署名），开关可隐藏、可用 ClippingPolygon 裁边界外。

## 五、已知限制

- **ClippingPolygon 只对凸多边形保证正确**；行政区划边界几乎都是凹的，凹处会多裁/少裁。做演示够用，正式展示用「裙边填充」路径（矢量裁剪的默认产物）。
- heightmap-1.0 是 Cesium 官方 deprecated 的格式（推荐 quantized-mesh），但 CTB 只产 heightmap、PRD 也要求只封装 CTB——Cesium 1.128 仍完整支持，可放心用。
- 前端工程不含在交付 zip 里；预览仍可用 CutMap 仓库根的 `terrain_viewer.html` + `serve.py`（零依赖，语义与前端工程一致）。
