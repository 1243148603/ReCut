# CutMap 验收改进说明（2026-10-27）

## 1. 改进背景

本轮依据《PRD V1.5》和《204DEM切片与地形瓦片教程》，在现有工程、重庆 30 幅 DEM、既有地形瓦片及自动化验收机制基础上继续验收。工作范围限定为缺陷修复、针对性回归和发布包更新，没有重写切片引擎，也没有重新下载或无条件重算整套 DEM。

行政区划数据按已批准的需求变更继续采用 DataV.GeoAtlas，来源、版本和 SHA-256 记录在 `resources/boundary-manifest.json` 中。

## 2. 本轮改进摘要

| 改进项 | 原问题 | 处理结果 |
|---|---|---|
| `layer.json` 范围 | 完整流程和 CLI 发布可能按瓦片网格包络写入 bounds，范围大于真实 DEM | 完整流程优先使用裁剪范围或实际 DEM 范围；独立打包且无 DEM 时才回退到瓦片包络 |
| 打包窗口布局 | “边界 GeoJSON”标签可能截断，底部按钮轻微越界 | 调整标签和内容高度；14 个窗体布局检查为 0 个问题 |
| 历史/配置原子写入 | Windows 索引器或安全软件瞬时占用目标文件时，连续删除、清空可能失败 | 对 `IOException`/`UnauthorizedAccessException` 增加有限退避重试 |
| 预设持久化验收 | 原有预设存储固定写入用户目录，不利于隔离回归 | 支持注入测试文件路径；正常用户路径及行为不变 |
| 回归覆盖 | 缺少 bounds、预设增改删、历史删除/清空的自动化检查 | 在既有 `WorkflowGate` 和 `AcceptanceGate` 内补充检查，没有新增同类测试框架 |
| Windows 发布包 | 旧包不含本轮产品修复 | 重新生成绿色版和 Inno Setup 安装包，并完成实际安装、升级、卸载验证 |

## 3. 主要代码变更

- `cutmap/src/CutMap.App/Jobs/PipelinePlan.cs`：将真实产品范围传入打包任务。
- `cutmap/src/CutMap.Cli/PackageCommand.cs`：CLI `publish` 在提供 GeoTIFF 时读取实际栅格范围。
- `cutmap/src/CutMap.App/Forms/PackageForm.cs`：修复标签和窗口底部布局。
- `cutmap/src/CutMap.Core/Store/AtomicFile.cs`：增加 Windows 瞬时共享冲突重试。
- `cutmap/src/CutMap.Core/Store/PresetStore.cs`：增加可选持久化路径，支持隔离测试。
- `cutmap/src/CutMap.App/Jobs/WorkflowGate.cs`：增加完整流程和仅前端流程的真实 bounds 回归。
- `cutmap/src/CutMap.Cli/AcceptanceGate.cs`：增加预设及历史持久化回归。

## 5. 已知限制

1. **NFR-05 性能未通过**：暖态包装层与直接命令行执行时间比约为 1.37～1.40，尚不能认定软件自身开销可忽略。
2. **NFR-06 米级高程一致性未通过**：25 个代表点相对源 DEM 的平均绝对误差为 2.644 米，最大绝对误差为 6.710 米。参考包与当前瓦片采样一致，因此不是本轮打包差异，但仍不满足教程规定的米级标准。
3. **Windows 10 实机尚未验证**：Windows 11 x64、中文界面和自包含运行已经验证；Windows 10 仍标记为 `BLOCKED_ENVIRONMENT`。
4. **真实外部下载源暂缓**：FR-06、FR-16 的本地模板、续传、404、超时、持久化逻辑已经通过，本轮未验证 Copernicus 或第三方镜像的实际连通性。
