# CutMap 开发与交接说明

这份文档写给**接手改这个项目的人**。它不重复代码里能读到的东西，
只记录两类内容：

1. **为什么这么做**——代码注释写不下、或者写散了会看不见的理由
2. **踩过的坑**——每一条都是实际撞出来的，不是推测

代码本身的注释很密（尤其 `CutMap.Core`），格式约定与业务口径在那边。

---

## 1 架构

```
CutMap.App (WinForms)         界面：向导、队列、历史、设置
      │  只通过 Job 抽象下发任务
CutMap.Cli (控制台)           无界面诊断与回归，不依赖窗口
      │
CutMap.Core                   全部业务逻辑，**一行 UI 代码都没有**
      ├── Geo/        GDAL 封装：栅格摘要、拼接裁剪、覆盖检查
      ├── Terrain/    瓦片网格算术、切片编排、layer.json、算法元数据
      ├── Tools/      ctb-tile 子进程
      ├── Vector/     行政区划边界
      ├── Download/   分幅枚举、URL 模板、下载器
      ├── Packaging/  打包与部署说明
      └── Store/      预设、历史、下载源、路径
```

**Core 不许依赖 UI**：这条不是为了好看，是为了让 `CutMap.Cli` 能在没有窗口的
环境下跑完所有验证。`.csproj` 里没有 `UseWindowsForms`，破了会编译不过。

**加任务类型只加一个 `Job` 子类 + 一个参数对话框**，不动主窗口。
`Job.Execute` 返回 `JobResult`，主窗口不知道也不关心任务内部在干什么。

## 2 关键决策与理由

| 决策 | 理由 |
|---|---|
| **GDAL 走绑定，ctb-tile 走子进程** | PRD §2 原文即如此（拼接裁剪用 GDAL 绑定，切片以子进程调用 ctb-tile）。CTB 没有可用的 C# 绑定，切片只能子进程。 |
| **GDAL 版本钉死 3.13.3** | 基线的 Checksum 58775 是验收锚点。NuGet 上 `MaxRev.Gdal.Core` 恰有 `3.13.3.580`，与 conda geo 的 GDAL 同版本号 → 不引入 warp 内核的版本偏移。**升级这个包必须重跑 `warp-gate`。** |
| **命名空间用 `CutMap.Core.Geo` 而不是 `.Gdal`** | 后者与 `OSGeo.GDAL.Gdal` 类撞名，每次引用都要写全限定名。 |
| **`ctb-tile.exe` 直接调，不调 `ctb.cmd`** | 批处理有两条硬约束：必须纯 ASCII（GBK 控制台下 UTF-8 中文注释会被当命令执行）、必须 CRLF（LF-only 会让 `goto :label` 按错误字节偏移找标签）。`Process.Start` + 显式设 `PROJ_DATA`/`GDAL_DATA` 完全绕开。 |
| **用户数据放 `%APPDATA%\CutMap`** | 开发期 exe 在 `bin\Debug\` 下，重编译会清目录；放 exe 旁边等于每改一次代码预设/历史/下载源就没一次。 |
| **zip 用 `NoCompression`** | `.terrain` 本身就是 gzip 流、GeoTIFF 是 LZW，再 deflate 只省千分之几，却要为 22 万个文件多花几分钟 CPU。 |
| **安装器自研，不用 Inno Setup** | 本机拿不到：winget 装它要管理员提权（非交互环境过不去），GitHub Releases 直连被墙。自研只需 .NET SDK，且能做**免管理员的按用户安装**。 |
| **载荷追加在 exe 尾部，不用嵌入资源** | 让打包脚本能只重跑拼接、不重编译安装器。几百 MB 的 `EmbeddedResource` 会让每次改一点内容就重编一遍。 |
| **行政区划数据用 DataV 而不是天地图** | 天地图 Key 已实际申请并实测，卡在它自己的权限类型判定（详见 §4）。脚本保留 `--source tianditu`，将来 Key 能用直接换。 |

## 3 文件命名：不要用中文

**软件产出过 `重庆市_dem.tif`，结果 ctb-tile 报 `could not open GDAL dataset`。**

原因不是 GDAL 不支持 Unicode（它支持），而是**路径经过控制台时会被按本地代码页
转换成乱码**。GUI 里走 Unicode 没问题，命令行调用、第三方工具、批处理全都会炸。

现在一律用**行政区代码**（`dem_156500000.tif`）——纯 ASCII 且唯一。
要给人看的中文名放在日志、元数据 json 和 `layer.json` 里。

这与 README §6.2 记录的 `.cmd` 必须纯 ASCII 是同一类坑：**只要有一个环节按本地
代码页解释文本，非 ASCII 就会在那里断掉。**

## 4 踩过的坑

### 4.1 ctb-tile 失败时退出码是 0

CTB 源码 `tools/ctb-tile.cpp` 的 `runTiler()` 有两条失败路径，行为**不一致**：

```cpp
if (poDataset == NULL) { cerr << "Error: could not open GDAL dataset"; return 1; }
try { ...切片... }
catch (CTBException &e) { cerr << "Error: " << e.what(); }   // 只打印
...
return 0;                                                     // ← 仍然返回 0
```

打开失败返回 1；切片中抛异常时打印完 `Error:` 照样返回 0。
**只看退出码会把一套坏瓦片当成功交付。**

`CtbTileRunner` 因此以 **stderr 为准**，并把实际瓦片数与预期对账。
`cli ctb-gate` 用「缺坐标系的栅格」**实测复现**了返回 0 那条路径。

### 4.2 `.gitignore` 的两个静默陷阱

- **不支持行内注释。** `cutmap/_gate/    # 说明` 整行被当成含注释文字的字面模式，
  规则等于没写。差一步就把 1.1 GB 提交进去。
- **无锚点的目录名会匹配任意层级。** 为 .NET 加的 `bin/` 把 `ctb/bin/` 那 49 个
  DLL 一并忽略了——那是 NFR-02 的交付物。必须写成 `cutmap/**/bin/`。

两个的共同点是：**文件还在磁盘上，只是 git 当它不存在**，不报错、不提示。

### 4.3 PowerShell 脚本必须 UTF-8 with BOM

`pack-*.ps1` 若无 BOM，Windows PowerShell 5.1 会按 ANSI（本机 GBK）解析，
中文注释被拆成乱码字节、引号配对错位，报的是「字符串缺少终止符」这类
**与真实原因无关**的语法错误。

另：`$PSScriptRoot` 在 `param()` 的默认值表达式里可能还是空的
（以相对路径 `-File` 调用时），改用 `$PSCommandPath` 在脚本体内推算。

### 4.4 `rm -rf` 会跟随目录联接

`dist/_view` 里有个 junction 指向 `cutmap/_gate/slice_full`。
**`rm -rf` 会跟随它把目标一起删掉。** 拆联接要用 `cmd /c rmdir`。

### 4.5 天地图服务端对 User-Agent 有过滤

同一个请求，UA 用 `CutMap/0.1` 会得到 **500 Internal Server Error**，
用浏览器 UA 才返回规范的 403 + JSON 错误。500 会把排查方向引向"参数写错了"。

另：天地图用 4xx 返回**有意义的 JSON**（如 `301013` 权限类型错误），
不读响应体就只剩一句 `HTTP Error 403`，把最关键的 `code`/`resolve` 全丢了。

### 4.6 分幅枚举的取整方向

四条边要**分两种取整**，统一用哪一种都会在"整度范围"上错一列：

- 西/南边界：它**落在**哪一幅里，那一幅就相交 → `floor`
  （105.3 落在 `[105,106]` 而不是 `[106,107]`）
- 东/北边界：那一幅若从边界**开始**，只在一个点接触，不算相交 → `ceil - 1`
  （110.0 落在 `[109,110]` 的末端，`[110,111]` 不该算）

最初四条边都写成 ceil/ceil-1，重庆范围只枚举出 **20 幅**而不是 30。
而 `105–110` 这种手填方式恰恰最常见。

### 4.7 直辖市没有"市辖区"那一层

行政区划代码 `gb` 是 9 位（3 位国家码 + 6 位区划码），**省/市/县长度完全一样**，
靠长度判断不了层级。

更麻烦的是**直辖市**：数据里没有"市辖区"层，区县直接挂在市下面。
巴南区 `156|500113` 的算术上级是 `156|500100`，这个节点根本不存在——
最初重庆的 38 个区县全挂空了。

修法不是给直辖市打补丁，而是**按实际存在的节点解析**：从候选编码往上找，
找到第一个真实存在的节点为止。直辖市、省直辖县一并落位。

### 4.8 真实行政边界会自相交

```
ERROR 1: Cutline polygon is invalid: Ring Self-intersection at ...
```

简化/合并过的边界数据很常见。合成数据是标准矩形，永远测不出来。

修法两步，**第二步是必须的**：`MakeValid` 修拓扑之后，还要**把多边形部分挑出来
重组成 MultiPolygon`**——MakeValid 对退化输入会把修不好的部分降级成线或点，
返回 GeometryCollection，而 cutline 必须是多边形，否则报
`Cutline not of polygon type`。

修不好时**退回原几何而不是静默换一个形状**：裁剪范围不能悄悄变，宁可让 GDAL 报错。

### 4.9 半像素：两种口径并存，各有用途

GLO-30 分幅的 `gt[0]=104.999861`（105 − 半像元）、`gt[3]=29.000139`（29 + 半像元）
——经纬度方向**符号相反**。

相邻分幅在两种口径下都严丝合缝，**contiguity 分不出来**，文件字节确实无法判定。
所以按用途分开：

| 用途 | 用哪个 | 为什么 |
|---|---|---|
| 瓦片计数 | `RasterInfo.Extent`（GDAL 像素外边缘） | 那是 **CTB 实际会去切的范围**。实测 `chongqing_dem.tif` 算出 `[105.3, 28.1, 110.2, 32.2]`，正是 `gdalwarp -te` 传入的值 |
| 覆盖判断 | `RasterInfo.PixelCentreExtent` | 按"原点存的是像素中心"还原出的**产品真实 footprint** |

差半个像元（约 15 m）。现实目标边距都在几十公里量级，不会翻转结论。

### 4.10 进度正则漏了最后一步

`GDALTermProgress` 的形状是 `0...10...20...90...100 - done in 00:03:21`：
中间每一步后面跟省略号，**但最后一步 100 后面没有省略号**，直接接 ` - done`。
只匹配 `(\d+)\.\.\.` 会让进度条永远停在 90%。

## 5 怎么扩展

### 加一种任务类型

1. 在 `CutMap.Core` 里写业务逻辑（无 UI 依赖）
2. 加一个 `Job` 子类，实现 `TypeName` / `Display` / `ParametersJson` / `Execute`
3. 加一个参数对话框（照 `SliceForm` 写）
4. 在 `MainForm.NewTask` 的分支里接上
5. 如果历史要能"重跑"，`ParametersJson` 里存的字段要够回填，并在
   `MainForm.RerunFromHistory` 里加一条分支

### 换行政区划数据源

`resources/fetch_boundaries.py` 是唯一的数据入口，产出三个 geojson，
字段只有 `name` + `gb`（含 156 前缀的行政区划代码）。
换源只要改这个脚本，**软件一行都不用动**（"数据即文件"）。

没有 `gb` 的要素会被自动滤掉（"境界线"），这是刻意的。

### 换 DEM 下载源

不用改代码：界面上「设置 → 下载源」可以增删改，URL 模板支持
`{name}` / `{lat}` / `{lon}` 三个占位符。内置的 Copernicus 官方源不可删（可禁用）。

## 6 验证入口

所有关键行为都有可复跑的命令，不依赖窗口：

```bash
cd D:/Map/cutmap
export PATH="$LOCALAPPDATA/Microsoft/dotnet:$PATH"

dotnet run --project src/CutMap.Cli -- warp-gate    # 拼接 Checksum 58775
dotnet run --project src/CutMap.Cli -- ctb-gate     # 退出码陷阱实测复现
dotnet run --project src/CutMap.Cli -- grid-gate    # 15 层瓦片数 223,495
dotnet run --project src/CutMap.Cli -- boundary     # 边界加载/过滤/矢量裁剪
dotnet run --project src/CutMap.Cli -- verify <瓦片目录> <源DEM>   # 前端可加载性
```

**改任何与瓦片网格或 GDAL 版本相关的代码后，跑 `grid-gate` 与 `warp-gate`。**
这两道闸门的意义是"证明工具自己的输出对不对"，它们错了比功能错更难发现。

> `baseline/` 只保留闸门读的三个文件（`manifests/tile_counts.txt`、
> `maxzoom_calibration/calibration_results.txt`、`.../res_3_3600.tif`）。
> 删其余部分时确认过：**代码只读这三个**，其余是留档。
> 需要它们可从 git 历史取（`bc845e9` 及之前）。

## 6.5 发布产物不进仓库

`dist/` 在 `.gitignore` 里：安装包与绿色版 zip 都是几百 MB 的二进制，
且可由 `pack-installer.ps1` / `pack-release.ps1` 一条命令重建。
新克隆下来没有现成的安装包，这是有意的——文档里写清楚怎么打，
比在仓库里塞 223 MB 二进制好。
